# 有限批次补采

## 目的与边界

解决旧日常更新无限发现帖子、列表请求间隔过短，以及“连续两页已入库就停止”导致分批补历史提前退出的问题。抓取仍使用项目现有牛客网关和 Playwright 正文提取，不引入新依赖。

新命令 `il backfill-crawl` 只抓取、保存新帖子，不调用 LLM、生成答案或重新抽取已有帖子。它与 `daily-update` 共用 PostgreSQL 队列、分页进度、详情请求预算和互斥锁。

这里只覆盖 tabId=818 的现有入口，没有扩展新的岗位频道。接口实际历史覆盖范围、排序是否稳定和网站限流策略尚未通过真实网站验证，不能保证补齐任意历史区间。

## 部署前置

先审查分支 diff，再按原有部署流程更新代码。现有数据库需要显式应用新增的 `sql/009_bounded_backfill.sql`：

```powershell
Get-Content sql/009_bounded_backfill.sql | docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U il -d interviewlens
```

该迁移只新增 `crawl_progress`、`crawl_queue`、`crawl_daily_budget` 和待处理队列索引，不改动历史帖子、题解或向量，也不自动删除记录。没有在现有业务 schema 中执行这份迁移。部署前运行旧代码的后台进程需要停止并更新，否则旧进程不会遵守新锁与预算。

## 手动运行

```powershell
# 第一批：可显式指定北京时间的起始日，也可不传 since
il backfill-crawl --since 2026-07-08 --batch 30 --daily 100

# 至少一小时后运行下一批。读取已保存的队列和进度，不必再传日期
il backfill-crawl --batch 30

# 只读取进度，不访问牛客
il backfill-status
```

未传 `since` 且首次建立进度时，使用数据库最新 `posted_at` 减七天作为起点；若没有任何日期，使用当前时间减九十七天。起点持久化后不随新增帖子移动。之后显式传入不同起点会报错，避免无意改变采集范围。缺少日期的记录仍会入队，不会被日期过滤丢弃。

## 约束与恢复语义

| 项目 | 行为 |
| --- | --- |
| 并发 | 同一数据库中补采与日常更新只能有一个抓取批次 |
| 单批 | 默认最多 30 次详情导航，允许调小，不允许大于 30 |
| 每日 | 默认最多 100 次详情导航，允许调小，不允许大于 100；北京时间自然日计数 |
| 列表 | 有待处理队列时不继续翻页；队列空时每批默认最多 3 页 |
| 请求间隔 | 列表和详情共用一个限速器：距上次请求开始至少 8 秒，再加 1～7 秒随机等待；首次请求也有随机等待 |
| 批次间隔 | 两次批次启动至少相隔一小时，包括失败或中断的批次 |
| 预算计费 | 详情导航前提交计数，超时、失败或进程崩溃均占用预算；列表请求单独受页数和批次间隔限制 |
| 重复帖子 | 队列 URL 唯一，入库 URL 唯一；已存在帖子只标记队列完成，不更新历史派生数据 |
| 临时失败 | 停止当前批次，保留链接；后续批次再尝试，最多三次后标记 failed |
| 网站拒绝 | 401/403/429、登录或验证页面、API 拒绝及异常结构会停止并持久化暂停原因 |

单批“30”与每日“100”是详情请求次数，不能理解为保证新增同样数量的帖子，也不包括页面自身加载的静态资源或站点内部请求。并发和间隔只控制程序主动发出的列表/详情导航。

排除登录、验证码或限流原因后，显式恢复：

```powershell
il backfill-crawl --resume-paused
# 排查某些 URL 三次失败的原因后再尝试；不返还已消耗的每日预算
il backfill-crawl --retry-failed
```

恢复选项仍然受一小时冷却和每日限额约束。普通网络失败不会自动循环重试；发现异常先结束批次。暂停判定采用 HTTP 状态、路径及短页面中的常见验证提示，有可能保守地误判；没有尝试绕过验证。

每页链接与分页进度在同一个短事务中提交，每篇帖子与其队列完成状态也在同一个事务中提交。中途退出后已经完成的部分不会丢失。PostgreSQL session advisory lock 跨进程互斥，异常或取消会释放，解锁失败时连接不会回到池中继续携带锁。

## 翻页策略和局限

只要接口返回有效记录，就不会因为它们全已入库而结束历史发现。保存 `next_page`；下一次发现从它前面两页开始回扫，随后继续前进。重叠页中的 URL 去重，不重复访问已完成详情。只有结构有效的空列表才标记本轮扫描完成；此后队列消费完，下轮从第一页重新检查新帖。

回扫两页只减轻小幅插入/重排的影响。页码分页没有服务器稳定游标，较大幅度重排、删除、置顶或接口历史上限仍可能导致漏项；不能将扫描完成等同于完整历史覆盖。应结合实际返回日期和独立抽样检查判断覆盖情况。起始日期仅用于逐条过滤，不假设整个列表严格按时间排序，因此遇到旧记录不会提前停止扫描。

## 现有命令变化

- `daily-update` 改为同样的有限抓取批次，抽取阶段只处理最多 30 篇 pending 帖子。暂停、失败、冷却、互斥或每日限额返回时，不继续执行模型流水线。成功后仍按原有行为聚合；答案生成仍由 `--no-answers` 控制。需要只补数据时应使用 `backfill-crawl`。
- `tab-crawl` 的 tab 模式和 `batch` 仅作为小样本文件导出，限制 1～3 页和最多 30 次详情请求，取消无限页模式。`tab-crawl --save-db` 会明确引导至新补采命令。
- `tab-crawl --source joblist` 仍是既有文件导出功能，没有纳入这次持久化补采。手动单 URL、Celery ingest 和旧进程同样不受新补采预算管理；不要与补采并行运行其他采集入口。
- 没有创建定时任务或启动真实网站抓取，也没有变更认证、公开 HTTP API、生产依赖或发布配置。

## 验证

回归测试不访问牛客或调用模型。PostgreSQL 集成测试需要显式设置 `IL_TEST_BACKFILL_DSN`，仅在随机生成的独立 schema 内建立测试表，结束后清理该 schema，不接触业务表。

```powershell
# PYTHONPATH 指向当前 worktree/src，避免共享 Python 环境导入旧 checkout
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python -m pytest tests/test_bounded_backfill.py -q

# 使用已配置的测试数据库连接；连接字符串不写入仓库
$env:IL_TEST_BACKFILL_DSN = $env:DATABASE_URL
python -m pytest tests/test_bounded_backfill_postgres.py -q
```

覆盖：队列去重、跨批续跑、已入库页之后继续前进、日期过滤、冷却、持久化暂停、失败计数、每日限额和日期切换、显式失败重试、不覆盖历史帖子、事务回滚、互斥、取消释放、请求间隔，以及日常更新停止后不继续调用模型。
